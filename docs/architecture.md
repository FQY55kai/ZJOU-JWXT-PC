# 实现办法（细节）

## 0. 前提：三条必须守住的不变量

1. **guest 内存布局原样保留。** 重编译后所有指针仍是主机地址；未重编译的代码直接跑原始机器码，读写同一块内存。任何"顺手改成原生结构体"的做法都会让两者对不上。
2. **ABI 原样保留。** 函数签名不变（Win64 寄存器约定）：`rcx/rdx/r8/r9` 传参，`rax` 返回，`xmm0` 传浮点，栈上 32 字节 shadow space。这样重编译函数与原始字节可以互相调用。
3. **每个函数可独立回退。** 一张表决定某个地址走重编译版本还是原始字节。覆盖率不需要 100% 才有产出。

## 1. 取边界（已实现，`tools/probe.py`）

PE 的 `.pdata` 是 `RUNTIME_FUNCTION` 数组，每项 12 字节：`BeginAddress / EndAddress / UnwindInfoAddress`（全是 RVA）。这就是函数表——不需要符号、不需要 PDB。实测覆盖 `.text` 的 92%；剩下的 8% 是没有异常展开信息的叶子函数，靠"前一函数结束处"顺推补齐。

同时对 `.reloc` 建立重定位表：`RIP` 相对寻址的指令在重编译后要换成"镜像基址 + 偏移"的常量，基址可在加载时随机（ASLR），也可固定。

## 2. 升举（lifter）

### 2.1 输入
一个函数 = 一段字节 + 起始 RVA + 重定位表 + 导入表（用于识别薄壳）。

### 2.2 步骤
1. **线性反汇编 → 基本块划分**。先按 Capstone 顺序扫，遇到分支目标/分支指令/`ret`/`int3` 断块。对 `jmp` 表（`jmp [rax*8+off]`）标记为间接跳转，需要数据流分析找取值范围；找不到就整体回退到原始字节（不是失败，是降级）。
2. **CFG 重建**。块→标签，条件跳转→`if (cond) goto L;`。**不做结构化还原**（不需要 `for/while`，`goto` 语义等价且不会错）。
3. **标志位建模**。只在"被读过"的地方算：对每个块做一次活跃性分析，`cmp/test` 之后若没有 `jcc/setcc/cmovcc/adc/sbb` 读标志，就不生成。实现上用一个小结构体：
   ```cpp
   struct Flags { uint8_t CF, PF, AF, ZF, SF, OF; };
   ```
   规则按 Intel SDM 逐条写，每条 ALU 指令一个 `set_flags_*()`；正确性由差分测试兜（见 §3）。
4. **子寄存器**。`eax/ax/al` 写入要掩码：`rax = (rax & ~0xFFFFFFFFull) | (v & 0xFFFFFFFFull)`；32 位写入顺带清零高 32 位（这是 x86-64 的语义，最容易写错的地方之一）。
5. **调用**。直接 `call rel32` → 查函数表，生成 `sub_<rva>(args...)` 调用；目标不在表内（导入/未覆盖）→ `call_original(<rva>, args...)`，走原始字节。间接 `call [reg]` → 先试 devirtualize（数据流上能确定唯一目标时直接调用），否则 `call_indirect(target)` 运行时查表。
6. **尾调用**。`jmp <函数入口>` → `return sub_<rva>(args...);`。这是 61% 的薄壳函数的形态，L1 的全部价值就在这里。

### 2.3 降级策略（关键）
任何一条指令不认识、任何一个块结构不确定，**整个函数**标记为 `ORIGINAL`，运行时直接跑原始字节。宁可少重编译一个函数，也不要生成可能出错的代码——因为出错的代价是"游戏在第 40 小时崩"，而不是"少 1% 性能"。

## 3. 差分 oracle（L3）

guest 与 host 同 ISA，这是本项目的核心优势：**原始实现不需要模拟器**。

```asm
; 输入：func 指针、寄存器快照数组、栈缓冲
mov [rip+old_rsp], rsp      ; 保存宿主栈
mov rax, [rcx+0]  ... 装入 16 个通用寄存器
mov rsp, rdx                ; 切到 guest 栈
call qword ptr [r8]         ; 调原始字节
mov rsp, [rip+old_rsp]
; 导出 16 个寄存器 + 内存校验和
```

流程：随机输入 → 原始字节跑一遍 → 重编译版本跑一遍 → 比较 `rax`、16 个通用寄存器、`xmm0-15`、以及被写内存页的哈希。

测试集来自**真实执行轨迹**（从游戏的正常运行里抓函数入口的寄存器快照），不是纯随机——纯随机会大量命中"永远不会发生的输入"，浪费测试预算。

产出：每个函数一个"已差分通过"标记。CI 每晚重跑全表，任何一个函数从不通过 → 通过 是**回归**，阻塞合并。

## 4. 运行时层（L4）

系统 API 面（实测导入）：

| 模块 | 符号数 | 处理 |
|---|---|---|
| MSVCP140 / VCRUNTIME140 | 136 | 直接转发到本机同名 DLL（同为 x64 版本，ABI 相同） |
| CRT api-ms-win-crt-* | 130 | 同上 |
| libHttpClient.GDK | 38 | 自己实现（HTTP 客户端） |
| Bink2Scarlett | 23 | 视频解码：接 Bink SDK 或完全跳过过场 |
| WS2_32 / WINHTTP | 40 | 转发 |
| xmem | 12 | 自己实现（主机内存分配语义） |
| 图形（无导入） | — | **静态链在镜像里**，必须靠重编译后的代码位置改（见 §5） |

实现方式：每个导入生成一个 `extern "C"` 桩，`import_table[<iat 槽位>] = &stub`。未实现的桩调用即 `abort()` 并打印参数——**宁可崩在第一次调用，也不要静默返回 0**（静默失败会让问题跑到几十层之外才爆）。

## 5. 图形层（L5）

现状（HLE 路线的实测）：每帧 4,544 条绘制、35,766 次调用、11,224 张描述符表，全部在 CPU 上重放；耗时 149 ms。

重编译路线下的目标结构：

1. **认出提交点**：重编译后的代码里，凡是构造绘制包、写描述符、提交命令的地方，都是普通函数调用——可以直接改代码。
2. **把"翻译"换成"记录"**：绘制不再逐条变成 D3D12 调用，而是压进一个紧凑的绘制数组（POD，无虚函数、无分配）。
3. **GPU-driven**：把绘制数组、描述符索引、剔除结果一起上传，由 compute 做剔除与参数整理，`ExecuteIndirect` 提交。CPU 每帧只做一次上传。
4. **描述符**：一次上传一整块"描述符表快照"，shader 用 `SM6.6` 的 heap 直接索引（resource binding tier 3 / `ResourceDescriptorHeap`），不再每帧重建 11,224 张表。

这一步之后，149 ms 的录制成本应该降到个位数毫秒；剩下的瓶颈会回到 GPU（当前 103 ms，这是主机 33 ms 的 3 倍，主因是 wave64 模拟与 DXIL 质量，换渲染器与 compute 重写热点后再评估）。

## 6. 已知的坑（提前记账）

| 坑 | 症状 | 对策 |
|---|---|---|
| 虚拟调用（C++ 虚函数表） | 间接 `call [vtable+off]` 遍地都是 | 数据流 devirtualize + 运行时查表回退；**不要**试图静态解析全部 |
| 异常（SEH/C++ EH） | 主机镜像里有 `.pdata` 展开信息，重编译代码没有 | 第一阶段：不重编译会抛异常的函数；第二阶段：把展开信息转成 PC 侧 SEH |
| TLS | 主机用 `.tls` 段 | 重编译后仍用同一段，通过 `gs` 索引映射 |
| 多线程 | 主机 24 个 worker | 保留线程结构不变，先求正确 |
| 指令缓存一致性 | 自修改代码（极少） | 检测 `VirtualProtect` 写可执行页 → 该区域整体回退原始字节 |
| 时间/计时器 | 帧率影响逻辑（30 fps 节流） | 运行时层拦截计时器，先按 30 Hz 逻辑时钟跑，再放开渲染帧率 |

## 7. 代码组织（建议）

```
tools/
  probe.py           取边界、统计、导入面          已实现
  lift.py            单个函数的升举与差分         已实现（直行子集）
  lifter/            正式实现（Rust，性能与可维护性）
    ir.rs            指令 → IR
    flags.rs         标志位规则
    emit.rs          IR → C++
  oracle/            硬件差分（Rust，asm 桩 + 快照回放）
runtime/             系统 API 静态实现
renderer/            L5
recomp/              生成代码（不进仓库）
```

选 Rust 做 lifter 的理由：30 万函数要跑得快、要能并行、要有测试；生成的 C++ 只为搭配现有工具链（MSVC 调试器、PIX）。
