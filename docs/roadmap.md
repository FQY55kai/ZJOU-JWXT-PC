> 裁判：`xmm0-15` 与 16 KiB arena 一起进比较，两侧逐例故障恢复（不再二分重跑）。
> 整函数 **125 例里 124 例（99.2%）** 逐寄存器、逐字节、逐向量寄存器一致；
> 另有**指令级 154 条 × 4 例 = 609 例全部一致**（`diff.py --snippets`，一条指令一个函数）。
>
> **下一件事按性价比排**（前 40,001 个函数只剩 50 个，且几乎全要动模型）：
> ① **`undecodable`（24）**——最大的一坨，但不是解码问题：线性解码全都能过，是某个跳转目标落在填充/数据里，
>    要处理它得先证明那条边走不到（数据流，不是解码）。
> ② **`cmpxchg16b`（7）**——16 字节原子比较交换，要一对寄存器 + `lock` 语义；单线程下只剩"比较全部 16 字节"+ ZF。
> ③ **PF（奇偶标志）**——`np`/`p` 一律拒绝（生产者没算过这一位，只剩 2 个）。要做得给每条 ALU 生产者补一个
>    "结果低 8 位的奇偶"、给合并点加第五个出口变量，而它只在 `jnp`/`setp` 这类极少见的消费处才有用。
> ④ **循环回边带来的标志**（`jne`/`setne` 共 4 个）：生产者不在这个函数能走到的地方，只能靠"沿回边传播"才有解，
>    而那是把当前的单遍数据流换成不动点迭代。
> ⑤ **`insertq`/`extrq`（4）**——SSE4a 的位段插入/抽取，两个立即数（起点与长度），语义与 `shld` 不同。
> ⑥ **x87 整族**（`F2XM1`/`FYL2X`/`FLD`/`FSTP`…）——80 位扩展精度，`double` 装不下；这一族在拒绝面里已不到 10 个函数。
> ⑦ **`0x18dc0` 这类"帧偏 8"**：`push` 与影子空间重叠时槽位整体错一格；已确认是桥的痕迹
>    （帧里那格存的是返回地址），差分精确到槽位，但要先有一条能比对帧布局的中间表示才谈得上分辨。
>
> 两轮前**收回**了更早一版的"明确不做"：`vrsqrtps`/`vrsqrtss`/`vrcpps`/`vrcpss` 与 `vfmadd*` 全部实现，
> 靠的不是表达式重写，而是**执行同一条指令**（`_mm_rsqrt_ps`/`_mm_fmadd_*` 就是它们）。
> 上一版判断"要拿到逐位结果表才能做"是对的，但那份表不用自己造——intrinsic 直接给了。
> 唯一代价是这几条指令要求宿主真的支持 AVX2/FMA，而原二进制本来就要求（否则它自己跑不起来）。

## M1.2 —— 真实地址空间（已完成）

原来的内存模型是 `stk + (addr & 255)`：把所有内存都当作那个 256 字节栈。真实函数第一句就是
`mov [rcx], rax`，写的是调用方给的缓冲区，于是被 `safe()` 整个滤掉——只有 2.5% 的函数能进差分。

- [x] `lift.py`：内存操作数直接 `*(uintN_t *)(uintptr_t)addr`，去掉 `stk` 与 `& 255`；`push`/`pop` 变真内存写；签名 `(r, stk)` → `(r)`
- [x] `oracle`：映像映射在首选基址、arena `VirtualAlloc` 在固定 0x20_0000_0000，两侧同址
- [x] 差分比**整个 arena（16 KiB）**，而不只是 16 个寄存器 + 256 字节栈
- [x] 解释器改成两段式地址空间（`Space`：映像 + arena），随发射器一起被验证
- [x] 桥：`guest_bridge` 让升举代码调用尚未升举的函数，否则只有 0.5% 的函数可测
- [x] `xmm0-15` 进比较（256 位 × 16 个向量寄存器，两侧由记录传入传出）

### 这一版修掉的六个错
每一个都值 8 字节或者一次 SIGSEGV，而且都不会自己暴露：

| 现象 | 原因 |
|---|---|
| 差分永远差 8 字节 | `call` 会把返回地址压进栈，裁判侧没有预充这 8 字节，于是 guest 看到的 `rsp` 整体偏一格 |
| 桥接调用整帧偏移 | 桥自己也要 `call`，预充值必须与"从裁判进入"时不同（8 / 0） |
| 升举过的调用不留返回地址 | 硬件 `call` 会在 `rsp-8` 写一个映像地址；升举成 C 调用后什么都不写，内存比不过 |
| 尾调用整帧偏移 8 | `jmp` 不压栈，但桥按 `call` 补偿了 8 |
| 桥一跳进映像就崩 | 映像被映射成 `PAGE_READWRITE`，代码页不可执行 |
| `ERROR_INVALID_ADDRESS`(487) | 生成的 `lifted.exe` 默认基址也是 `0x1_4000_0000`，把映像的首选基址占了 |

**验收**：`--limit 120` 里"能跑"的比例 **66%（79/120）**，目标 ≥60% 达成；其中 35 个（44%）能和硬件逐字节对上，其余是因为函数读了从未初始化的全局而两侧同时崩溃。

### 这一版修掉的两个错

| 现象 | 原因 |
|---|---|
| `cmp ecx, -2; jb` 判反 | 立即数符号扩展到 64 位，比较按 64 位无符号做 |
| `cmp eax, -1; setne al` 多置一位 | 同上，但发生在**相等**比较上：`0x00000000FFFFFFFF` 与 `0xFFFFFFFFFFFFFFFF` 不等 |

## M1.4 —— 指令级验证，与它抓到的三个语义错（已完成，75.6% → 81.5%）

这一轮的主目标不是"再多接受一些"，而是**让接受的东西真被执行过一次**。整函数差分的样本里

- [x] `--snippets`：一条指令一个函数，字节**从映像里抄**（不写汇编器），写进 `.text` 里一段无人拥有的

- [x] `vpsignb`/`vpsignw`/`vpsignd`（按元素符号取反/清零/保留）、`vinsertps`（三段立即数）、

      `vcvttss2si`/`vcvttsd2si`（NaN 与越界给整数不定值）
- [x] `rol`/`ror`：只写 CF/OF，保留 ZF/SF/PF ⇒ 新增 `cmp_nocf` 状态
- [x] `vtestps`/`vtestpd`/`ptest`：标志生产者，进 `pending`（`kind == "vtest"`）
- [x] `cmp` 的 `s`/`ns`（差的符号，不是任一操作数的符号）与 `o`/`no`（`(a^b) & (a^diff)` 的最高位）
- [x] `setcc` 不清 `pending`：`cmp a,b / sete al / setb cl` 是编译器常规输出
- [x] 零操作数白名单：`cdqe` 在映像里出现 331 次，全部被"零操作数即拒绝"的守卫挡住

### 三个被差分抓出来的语义错

| 现象 | 真因 |
|---|---|
| `test byte ptr [rcx+0xb0], 1` 方向反了 | ZF/SF 来自 **`SRC1 AND SRC2`**，不是 `SRC1`。只取第一个操作数 = 每条位测试都变成"非零即真" |
| `vtestps` 后的 `jz` 整条反 | `ZF = ((SRC1 AND SRC2) == 0)`、`CF = ((SRC2 AND NOT SRC1) == 0)`——与落 ZF、与非落 CF；且 VTEST* **只比符号位**。两条错叠在一起时 `vtestps x, x` 看不出来 |
| 向量测试"只在移植侧崩" 2 例 | `lane_at()` 是通道的**值**，被当成地址转型；逐字节读要的是 `lane_ptr()`（通道的**地址**） |

**验收**：`cover.py --sample 40001` 报 **81.5%**（32,593）；整表 **85.8%**（256,729 / 299,257）；
`diff.py --snippets` **252/252**；`diff.py --limit 400 --branches --rounds 3` **138/141**。
`0x18dc0` 仍然不一致（`push` 与影子空间重叠，帧内偏移差 8），留在这里没有绕开。✅

### 这一轮之后，优先顺序变了

拒绝面现在的前五项里，三项是**故意拒绝**（`vrsqrtps`/`vrsqrtss` 992、`vfmadd*` 1,476、`vrcpps` 207），
一项是**结构性的**（跨基本块的标志：1,081），剩下一项是"再加一张表"（`vpmovsxbq` 146）。所以：

1. **跨基本块的标志**是唯一还值得动结构的地方：`je`/`jne`/`jnp`/`cmovb` 的消费者在另一条边进来，
   生产者在别的块里。做法不是放宽守卫（那会在真正的"读未定义标志"上静默出错），而是把标志当成
   **块的出口状态**：块结束时若 `pending` 非空且后继唯一，就把它带到后继去。
2. **x87 整族**（`F2XM1`/`FYL2X`/`FYL2XP1`/`FLD`/`FSTP`…）是最大的一块空白。80 位扩展精度不能用
   `double` 假装，要么用 `long double`（MSVC 上就是 64 位，不行），要么自己写 80 位定点。
3. **`sqrt` 的 DAZ/NaN 边界**：上游 `5f51daaa` 的解法是把 `SQRTSD` 交给处理器（`_mm_sqrt_sd`）。
   我们这边只要把 `VEC_SQRT` 的标量形式换成 intrinsic，就能在**不建模 MXCSR** 的前提下把这条边界消掉。

## M1.4b —— 把"故意拒绝"收回：84.2% → 96.3%（已完成）

## M1.4c —— 把标志变成状态：96.3% → 99.7%（已完成）

这一轮不动架构，只把"标志"这件事继续往硬件的方向推：CF 变成数据流里的**值**，合并点变成
**变量**，然后按拒绝面从大到小把指令族一条条补上。

- [x] **`adc`/`sbb`**（→ 38,843）：它们**读** CF，所以 `carry_expression()` 把每种生产者的进位写成
      一个 0/1 表达式（`cmp` 是"低于"、`test`/逻辑运算是 0、`adcsbb` 取上一条的进位）；
      `_addcarry_u64`/`_subborrow_u64` 就是 ADC/SBB 本身。算不出来的（`inc`/`dec` 不动 CF、
      `rol`/`ror` 拿不到旧 CF）如实拒绝
- [x] **多入边同 token 继承**（→ 38,950）：判据从"入边数 == 1"改成"所有入边的出口 token 相同"——
      同一个 token 意味着同一条产生指令跑过、快照是同一批变量，取哪条路都是同一个值
- [x] **合并点把标志落成变量**（→ 39,147）：入边留下**不同** token 时，每条出口在离开前写
      `fz_/fs_/fc_/fo_<块首>`，块首按变量读。可用集合取交集，消费者要一位不存在的标志照旧拒绝；
      没人读的合并点整个撤掉。顺带修掉 `flag_step` 里"产生者"排在"破坏者"之后的顺序错
- [x] **立即数移位的四个标志 / `tzcnt`·`lzcnt`**（→ 39,507）：计数为 0 时标志不动（SDM），
      所以只认立即数非零；`tzcnt` 的 ZF/CF 说的是"源是零"，而源为零时**结果**是位宽。
      同时把 `VEC_STEMS` 补全（`VEC_ROUND`/`VEC_EXTEND`/`VEC_PACK` 与手写分支里的那些名字都不在里面），
      向量指令不再被当成"改了标志"的破坏者

## M1.4d —— 拒绝面的尾巴：99.7% → 99.8%（已完成）

这一轮不做架构，只按拒绝面从大到小收：先收 100+，再收 60+，最后收 20+。剩下的每一条都是
"要么动模型、要么设计一条辅助函数"的东西（见文首"下一件事"）。

- [x] **`bt`/`bts`/`btr`/`btc` 的内存形式**（→ 169 个函数）：内存目标的位号是**有符号值**——
      字节地址 `基地 + (位号 >> 3)`（算术右移）、位 `位号 & 7`；寄存器形式相反，在操作数宽度内取模。
      两条规则不能合并。**立即数形式不跨字节**（位号在宽度内取模、地址停在原处）。
      这个映像里的内存形式**只以 `lock` 出现**（`lock btr [mem], reg` 55 条、`lock bts` 26 条），
      而 `lock` 在单线程移植里只剩"指令本身"，所以照常发射
- [x] **`phaddw`/`phaddd`/`phsubw`/`phsubd`/`phaddsw`/`phsubsw`**（→ 71）：与 `haddps`/`haddpd`
      是**同一条规则换元素宽度**（每 128 位通道内两两合并、源1 在前源2 在后）。所以把
      `VEC_HADD` 的值从"步长"改成"(步长, 类型, 运算)"三元组，加表就能覆盖整数与减法；
      只有 `*SW` 两条要夹到 `int16`（不能用 C 的 `+`）
- [x] **`mul`/`imul` 的单操作数形式**（→ 67）：`RDX:RAX` 的**双倍宽度**乘积，`_umul128`/`_mul128`
      就是它们；8/16 位形式也在内（`AX`/`DX:AX`），因为乘积总装得下，**没有 `#DE` 风险**
- [x] **`vpslldq`/`vpsrldq`**（→ 18）：按字节在整个 128 位里移，计数 > 15 整个清零。
      **VEX 形式的目的寄存器不是源**——片段差分判 0/4，见下
- [x] **`vperm2f128`/`vperm2i128`**（→ 26）：两个源按 128 位拼四格、`imm[3]`/`imm[7]` 各清一半
- [x] **`vcvtps2ph` 的内存目标**（→ 23）：只是换一个落点，没有"其余清零"这回事
- [x] **`vcvttpd2dq`**（→ 12）：截断不读 MXCSR，所以它能从 `vcvtpd2dq` 里单独做出来

**验收**：`cover.py --sample 40001` 报 **99.8%**（39,916 / 40,001，上一轮 39,875）；整表
**99.8%**（298,565 / 299,257，上一轮 297,979）；`diff.py --snippets` **580/580**（145 条 × 4 例）；
`diff.py --limit 400 --branches --rounds 3` **124/125**，与上一轮同一例不一致（`0x18dc0` 的帧槽位）、
同样 3 例只在移植侧崩——新增的接受量没有带进新的不一致。✅

### 这一轮片段差分抓到的两处

| 指令 | 错法 | 现象 |
|---|---|---|
| `vpsrldq`/`vpslldq` | 照 legacy 形式写成"就地移"，VEX 的三操作数形式里目的寄存器不是源 | 0/4；必须先 `memcpy` 一格再移 |

## M1.4e —— 标志白名单与三条"有定义却没建模"的位（已完成）

这一轮的两个入口都不是"再加一条指令"，而是**探针**：

1. `jcc/setcc/cmovcc` 报 "without a compare" 的 30 来个函数，逐个把**真正被拒的那条指令**
   从异常回溯里取出来（第一版从消息里猜助记符，猜中的是函数里第一条同名指令，误导了一轮）。
2. 顺着"未定义不是零"这条原则，把 `mul`/`bzhi` 这两位**有定义**的标志补上。

- [x] **`rorx` 补进 `FLAG_SAFE`**（→ 找回 `cmp / rorx / cmovbe` 这一类）：它是 BMI2 的循环右移，
      **不写标志正是它与 `ror` 的全部区别**，§7 早就引了 SDM 那一句，可白名单里没有它。
      同时补齐同类漏项：`movbe`、`mfence`/`lfence`/`sfence`、`clflush`、`vzeroupper`/`vzeroall`、
      `prefetch*`（按前缀判，助记符有六个）
- [x] **`bzhi` 的标志**：ZF/SF 是结果的、CF 是"索引 ≥ 宽度"（取索引低 8 位）、OF 清零，
      AF/PF 未定义 ⇒ 只承认这四个里的三个。发射侧要给 `pb_` 存**第三个**操作数（索引），
      不是第二个——这是它与 add/sub 唯一不同的地方
- [x] **`mul`/单操作数 `imul` 的 CF/OF**：两者说的是同一件事"高半里有超出低半的东西"，
      无符号看非零、有符号看符号扩展。新增 token 类型 `mulf`（只有 c/o 两位可用），
      发射侧自己算 `pcl_`/`pch_` 一对（`lift_one` 把高半藏在块的局部变量里，外面读不到）。
      **`mul` 之后 `jz` 仍然拒绝**：ZF 未定义，跳过它就是猜
- [x] **`vpalignr`**：两源拼成 32 字节右移 imm 个**字节**，256 位形式在每个 128 位通道内部各拼各的，
      `imm > 31` 结果全零（不是取模）
- [x] **`vpermilps` 变量形式**：控制字**逐元素**给（每格低两位选同通道内的哪一格），
      与立即数形式是两条指令。这个映像里 6 条全是 `[rip+常量]` 的控制字，片段搬不走，
      所以它只有整函数差分能看到（片段表里如实记 "not in the image"）
- [x] **`vmovntps`/`vmovntpd`/`vmovntdq`/`vmovntdqa`**：非临时存储只改缓存提示，
      数据落点与 `movaps` 逐字节相同；没有缓存模型就没有可区别的东西
- [x] **`tools/why.py`**：把"哪条指令真的被拒"变成一条命令。这三处修正全都是靠它定位的——
      `cover.py` 的直方图能排序，但不能告诉你在哪个函数、哪条指令上

**验收**：`cover.py --sample 40001` 报 **99.8%**（39,922 / 40,001，上一轮 39,916）；整表 **99.8%**
（298,606 / 299,257，上一轮 298,565）；`diff.py --snippets` **584/584**（147 条 × 4 例，
`bzhi` 读四个标志、`mul`/`imul` 读 c/o）；整函数差分 **124/125**，仍是 `0x18dc0` 那一例。✅

### 这一轮的教训（写给下一轮的自己）

- **白名单漏一项，报错报在消费者身上**：`cmovbe without a compare` 里的 `cmovbe` 是无辜的，
  错的是两张表里的第二张。所以"拒绝面直方图"只能用来排序，定位必须靠回溯。
- **未定义 ≠ 零**：`mul` 的 ZF、`blsi` 的 CF、`tzcnt` 的 SF 都属于这一类。把它们当 0 会**通过**
  差分（测试数据撞不上那个位），然后在真机上出错——这是最坏的一种"对"。

## M1.4f —— 除法与"借硬件执行环境"（已完成）

这一轮的两条入口都是**上一版自己写下的"要动模型"**，结果两条都不必动模型：

1. `div`/`idiv` 的窄形式（8/16/32 位）——上一版判断"要移植 `#DE`，这是一条设计决定"。决定是：
   **故障用 `RaiseException(0xC0000094)` 发**，它就是硬件 `#DE` 在 Windows 上的那个码。
2. `vcvtps2dq`——上一版判断"MXCSR 不在模型里，要么把 MXCSR 记进用例，要么只做不要舍入的那一半"。
   第三条路：让硬件再执行一次（`_mm_cvtps_epi32` 就是那条指令，两侧读同一份 MXCSR）。

- [x] **`div`/`idiv` 的 8/16/32 位形式**：被除数是 `AX`、`DX:AX`、`EDX:EAX`，商的落点是 `AL`/`AH`、
      `AX`/`DX`、`EAX`/`EDX`。顺带发现**32 位形式的被除数一直拼错**：`_udiv128` 的头两个参数是
      **高 64 位**，而 `EDX` 只是高 32 位——被除数等于被乘了 2^32，且这个错把 #DE 的时机一起改了，
      所以差分里看着"两边都崩"。只有 64 位形式真的需要 128÷64
- [x] **`#DE` 的三条阈值**：除零、商越过 `2^bits`、商越过 `2^64`（`_udiv128` 只认最后一条）。
      窄形式自己判前两条，`fault_divide()` 发故障
- [x] **`fault_divide` 必须是调用，不能是一段纯运算**：`if (q > mask) q = _udiv128(d, 0, d, &rem)`
      会被 /O1 if-convert 成无条件执行，商没越界的那一支也跟着崩（汇编里那行判断整段消失）
- [x] **界的字面量要带 `LL`**：`-2147483648` 不是负数字面量，比较退化成**无符号**比较，恒真 ⇒
      每一次除法都 #DE。这一条与上一条叠在一起时，现象是"片段只在端口里崩"
- [x] **`SNIPPET_SEED`**：片段可以声明要压住的寄存器。16 位 `div` 的被除数是 `DX:AX`，随机种子下商
      几乎必然越界，4 个用例全变成"两侧都崩"，既不算比对也证明不了东西；压住被除数那一半、除数仍然随机
- [x] **`vcvtps2dq`/`vcvtpd2dq`**：`_mm_cvtps_epi32`/`_mm_cvtpd_epi32` 就是它们，舍入模式、越界与 NaN 的
      "整数不定值"逐位相同
- [x] **`vcvtps2ph` 的 `imm[2]`**：`_MM_FROUND_CUR_DIRECTION` 就是 imm8 的 bit 2，不再拒绝
- [x] **`vaesimc`（顺带 `aesenc`/`aesdec`/`aesenclast`/`aesdeclast`）**：上游这一轮新增的 AES-NI。
      这个映像里只有 `aesimc` 的 VEX 形式（13 条），`_mm_aesimc_si128` 就是它；顺带被片段差分抓到
      "一源形式把目的当成了源"（0/4，见 README §5⑧）。`PCLMULQDQ` 这个映像里一次都没有，不写

**验收**：`cover.py --sample 40001` 报 **99.9%**（39,952 / 40,001，上一轮 39,922）；整表 **99.8%**
（298,762 / 299,257，上一轮 298,606，其中 AES 只多 1 个函数——`vaesimc` 出现在 13 条指令里，其余
12 个函数另有拒绝原因）；`diff.py --snippets` **609/609**（154 条 × 4 例，`--rounds 6` 时 913/913；
`div`/`idiv` 三种宽度各一条）；整函数差分 **124/125**，仍是 `0x18dc0` 那一例。✅
反证：把 32 位的被除数改回错误拼法，片段差分立刻报 `fault only in the port`（`div/oneop32`）。

### 这一轮的教训（写给下一轮的自己）

- **不能拿"会崩的指令"当控制流**：编译器有把纯运算搬出分支的自由，故障发生在它搬走之后。
  想让一段代码**一定**执行，就得让它有副作用（一次调用、一次 `volatile` 写）。
- **类型是语义的一部分**：`-2147483648` 的类型不是"负的 int"。一个"显然为假"的比较把每一次除法
  都判成了故障，而报错信息（`fault only in the port`）指向的是除法，不是比较。
- **同一个现象有三种解释时，读代码没用**：把中间值写进 `volatile`、看汇编折成了什么，比再读一遍源码快。
