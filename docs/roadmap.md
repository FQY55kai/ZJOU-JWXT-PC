# 路线图

> **2026-11-26 停在这里，从这里接着做**：`tools/` 下已有 probe / lift / branch / diff / callgraph / functable / cover / shape。
> oracle 可跑；子寄存器、`movabs`、`[rip+d]`、`gs:` 段、`div`、ALU/BT/浮点比较标志、CFG + 跳转表、
> 256 位向量文件、间接调用/跳转的派发表、`lock` 家族、BMI1/BMI2 位指令、`vpsignb`/`vinsertps`/`vsqrt*`/
> `vtest*`/`rol`·`ror`、**跨基本块的标志数据流**、**近似指令 `rsqrt`/`rcp`**、**FMA 全 24 形态**、
> **32 个 AVX 比较谓词**、**`vround*`/`vpack*`/`vpshuf*`/`vextracti128`/`vinserti128`/`vcvtps2ph`**、
> **ALU 的 CF/OF 反推** 都已通，分支通道接受 **38,534 / 40,001（96.3%）**，整表 **290,562 / 299,257（97.1%）**。
>
> 裁判：`xmm0-15` 与 16 KiB arena 一起进比较，两侧逐例故障恢复（不再二分重跑）。
> 整函数 **122 例里 121 例（99.2%）** 逐寄存器、逐字节、逐向量寄存器一致；
> 另有**指令级 100 条 × 5 例 = 500 例全部一致**（`diff.py --snippets`，一条指令一个函数）。
>
> **下一件事按性价比排**：
> ① **`adc`/`sbb`（约 350）**——它们是 CF 的**消费者**，而 CF 现在只是一个"分支条件"，
>    不是数据流里的**值**。要让 CF 变成值，`pending` 得同时携带"CF 的表达式"与"其余标志的表达式"，
>    两条进位链（`adc` 接 `adc`）才连得起来。这是唯一还值得动结构的一块。
> ② **跨两条入边的标志合并**（`je`/`jne`/`cmovb` without a compare，约 560）——
>    单入边已经吃掉了；两条入边时两条路径可能留下不同标志，选任何一条都是猜。**如实拒绝**比猜对更重要。
> ③ **x87 整族**（`F2XM1`/`FYL2X`/`FYL2XP1`/`FLD`/`FSTP`…）——80 位扩展精度，`double` 装不下。
> ④ **`0x18dc0` 这类"帧偏 8"**：`push` 与影子空间重叠时槽位整体错一格；已确认是桥的痕迹
>    （帧里那格存的是返回地址），差分精确到槽位，但要先有一条能比对帧布局的中间表示才谈得上分辨。
>
> 这一轮**收回**了上一版的"明确不做"：`vrsqrtps`/`vrsqrtss`/`vrcpps`/`vrcpss` 与 `vfmadd*` 全部实现，
> 靠的不是表达式重写，而是**执行同一条指令**（`_mm_rsqrt_ps`/`_mm_fmadd_*` 就是它们）。
> 上一版判断"要拿到逐位结果表才能做"是对的，但那份表不用自己造——intrinsic 直接给了。
> 唯一代价是这几条指令要求宿主真的支持 AVX2/FMA，而原二进制本来就要求（否则它自己跑不起来）。

## M1.2 —— 真实地址空间（已完成）

原来的内存模型是 `stk + (addr & 255)`：把所有内存都当作那个 256 字节栈。真实函数第一句就是
`mov [rcx], rax`，写的是调用方给的缓冲区，于是被 `safe()` 整个滤掉——只有 2.5% 的函数能进差分。

- [x] `lift.py`：内存操作数直接 `*(uintN_t *)(uintptr_t)addr`，去掉 `stk` 与 `& 255`；`push`/`pop` 变真内存写；签名 `(r, stk)` → `(r)`
- [x] `oracle`：映像映射在首选基址、arena `VirtualAlloc` 在固定 0x20_0000_0000，两侧同址
- [x] 差分比**整个 arena（16 KiB）**，而不只是 16 个寄存器 + 256 字节栈
- [x] 解释器改成两段式地址空间（`Space`：映像 + arena），随发射器一起被验证
- [x] 桥：`guest_bridge` 让升举代码调用尚未升举的函数，否则只有 0.5% 的函数可测
- [x] `xmm0-15` 进比较（256 位 × 16 个向量寄存器，两侧由记录传入传出）

### 这一版修掉的六个错
每一个都值 8 字节或者一次 SIGSEGV，而且都不会自己暴露：

| 现象 | 原因 |
|---|---|
| 差分永远差 8 字节 | `call` 会把返回地址压进栈，裁判侧没有预充这 8 字节，于是 guest 看到的 `rsp` 整体偏一格 |
| 桥接调用整帧偏移 | 桥自己也要 `call`，预充值必须与"从裁判进入"时不同（8 / 0） |
| 升举过的调用不留返回地址 | 硬件 `call` 会在 `rsp-8` 写一个映像地址；升举成 C 调用后什么都不写，内存比不过 |
| 尾调用整帧偏移 8 | `jmp` 不压栈，但桥按 `call` 补偿了 8 |
| 桥一跳进映像就崩 | 映像被映射成 `PAGE_READWRITE`，代码页不可执行 |
| `ERROR_INVALID_ADDRESS`(487) | 生成的 `lifted.exe` 默认基址也是 `0x1_4000_0000`，把映像的首选基址占了 |

**验收**：`--limit 120` 里"能跑"的比例 **66%（79/120）**，目标 ≥60% 达成；其中 35 个（44%）能和硬件逐字节对上，其余是因为函数读了从未初始化的全局而两侧同时崩溃。

### 这一版修掉的两个错

| 现象 | 原因 |
|---|---|
| `cmp ecx, -2; jb` 判反 | 立即数符号扩展到 64 位，比较按 64 位无符号做 |
| `cmp eax, -1; setne al` 多置一位 | 同上，但发生在**相等**比较上：`0x00000000FFFFFFFF` 与 `0xFFFFFFFFFFFFFFFF` 不等 |

两条都是"快照是 64 位、语义是 32 位"。**这个错误类型出现了两次，说明它还会出现第三次**——
下一次写任何新的标志消费者，第一件事是问"操作数宽度是多少"，而不是"值对不对"。

**验收**：`python tools/cover.py --sample 40000` 报 75.6%；差分 80 例里 78 例全部三项一致。✅

## M1.4 —— 指令级验证，与它抓到的三个语义错（已完成，75.6% → 81.5%）

这一轮的主目标不是"再多接受一些"，而是**让接受的东西真被执行过一次**。整函数差分的样本里
201 / 262 个函数两侧同样崩溃（读文件里为 0 的全局），这条指令就从未运行；按函数算的"一致率"
再高，也盖不住"刚加的那一族指令根本没被测到"。

- [x] `--snippets`：一条指令一个函数，字节**从映像里抄**（不写汇编器），写进 `.text` 里一段无人拥有的
      填充区，`ret` 收尾，只通过标志说话的再接四个 `setcc`；补丁打在**映像副本**上，两侧映射同一份 —— 42 条 × 6 例 = 252 例，全一致
- [x] `vpsignb`/`vpsignw`/`vpsignd`（按元素符号取反/清零/保留）、`vinsertps`（三段立即数）、
      `vmovshdup`/`vmovsldup`/`vmovddup`（gather，含 `m64` 源）、`vsqrtps/pd/ss/sd`（正确舍入）、
      `vcvttss2si`/`vcvttsd2si`（NaN 与越界给整数不定值）
- [x] `rol`/`ror`：只写 CF/OF，保留 ZF/SF/PF ⇒ 新增 `cmp_nocf` 状态
- [x] `vtestps`/`vtestpd`/`ptest`：标志生产者，进 `pending`（`kind == "vtest"`）
- [x] `cmp` 的 `s`/`ns`（差的符号，不是任一操作数的符号）与 `o`/`no`（`(a^b) & (a^diff)` 的最高位）
- [x] `setcc` 不清 `pending`：`cmp a,b / sete al / setb cl` 是编译器常规输出
- [x] 零操作数白名单：`cdqe` 在映像里出现 331 次，全部被"零操作数即拒绝"的守卫挡住

### 三个被差分抓出来的语义错

| 现象 | 真因 |
|---|---|
| `test byte ptr [rcx+0xb0], 1` 方向反了 | ZF/SF 来自 **`SRC1 AND SRC2`**，不是 `SRC1`。只取第一个操作数 = 每条位测试都变成"非零即真" |
| `vtestps` 后的 `jz` 整条反 | `ZF = ((SRC1 AND SRC2) == 0)`、`CF = ((SRC2 AND NOT SRC1) == 0)`——与落 ZF、与非落 CF；且 VTEST* **只比符号位**。两条错叠在一起时 `vtestps x, x` 看不出来 |
| 向量测试"只在移植侧崩" 2 例 | `lane_at()` 是通道的**值**，被当成地址转型；逐字节读要的是 `lane_ptr()`（通道的**地址**） |

**验收**：`cover.py --sample 40001` 报 **81.5%**（32,593）；整表 **85.8%**（256,729 / 299,257）；
`diff.py --snippets` **252/252**；`diff.py --limit 400 --branches --rounds 3` **138/141**。
`0x18dc0` 仍然不一致（`push` 与影子空间重叠，帧内偏移差 8），留在这里没有绕开。✅

### 这一轮之后，优先顺序变了

拒绝面现在的前五项里，三项是**故意拒绝**（`vrsqrtps`/`vrsqrtss` 992、`vfmadd*` 1,476、`vrcpps` 207），
一项是**结构性的**（跨基本块的标志：1,081），剩下一项是"再加一张表"（`vpmovsxbq` 146）。所以：

1. **跨基本块的标志**是唯一还值得动结构的地方：`je`/`jne`/`jnp`/`cmovb` 的消费者在另一条边进来，
   生产者在别的块里。做法不是放宽守卫（那会在真正的"读未定义标志"上静默出错），而是把标志当成
   **块的出口状态**：块结束时若 `pending` 非空且后继唯一，就把它带到后继去。
2. **x87 整族**（`F2XM1`/`FYL2X`/`FYL2XP1`/`FLD`/`FSTP`…）是最大的一块空白。80 位扩展精度不能用
   `double` 假装，要么用 `long double`（MSVC 上就是 64 位，不行），要么自己写 80 位定点。
3. **`sqrt` 的 DAZ/NaN 边界**：上游 `5f51daaa` 的解法是把 `SQRTSD` 交给处理器（`_mm_sqrt_sd`）。
   我们这边只要把 `VEC_SQRT` 的标量形式换成 intrinsic，就能在**不建模 MXCSR** 的前提下把这条边界消掉。

## M1.4b —— 把"故意拒绝"收回：84.2% → 96.3%（已完成）

这一轮从设备层面把上一版列为"明确不做"的两族收回，并且都是**执行同一条指令**，不是重写语义。

- [x] **跨基本块的标志数据流**（32,593 → 33,690）：`flag_flow()` 迭代到不动点，只让**单入边**块继承
      前驱的出口 token；标志操作数改按**产生指令的地址**命名（`pa_<at>`/`pb_<at>`…），
      于是消费者在三个块之外也能引用它。`cmovcc` 与 `setcc` 一样只读标志、不写标志 ⇒ 不再清 `pending`
- [x] **近似指令**（→ 33,711）：`_mm_rsqrt_ps`/`_mm_rsqrt_ss`/`_mm_rcp_ps`/`_mm_rcp_ss` 就是那四条指令
- [x] **FMA 全 24 形态**（→ 36,302）：`_mm_fmadd/fmsub/fnmadd/fnmsub_{ps,pd,ss,sd}`；标量形式的
      `127:32` 由硬件判定为**保留目标原值**（与 `sqrtss`/`roundss` 的 `SRC1` 规则不同，见 README §5⑥）
- [x] **32 个 AVX 比较谓词**（→ 37,389 的一部分）：`_oq`/`_os`/`_uq`/`_us` 只影响异常，掩码同义 ⇒ 折叠
- [x] **`vround*`/`vpack*`/`vpshuf*`/`vpextr*`/`vinserti128`/`vextracti128`/`vcvtps2ph`/`vcvtph2ps`**；
      `vpackus*` 的源是**有符号**的（按无符号读会把 `-1` 夹成 `255` 而不是 `0`）
- [x] **`vptest`**（进标志模型，与 `ptest` 同一 `vtest` token）
- [x] **ALU 的 CF/OF 反推**（→ 38,534）：另一个操作数不必另存，`add` 的被加数是 `结果-源`、
      `sub` 的被减数是 `结果+源`；`inc`/`dec` 单独给 OF（不动 CF 的条件如实拒绝）
- [x] **`bts`/`btr`/`btc` 的 CF、`popcnt`、`bzhi`、`rorx`**；`popcnt` 用逐位归并而非 `__popcnt`
      （没开 `/arch:SSE4.2` 时它会退化成运行库调用、链接不上）

**验收**：`cover.py --sample 40001` 报 **96.3%**（38,534）；整表 **97.1%**（290,562 / 299,257）；
`diff.py --snippets` **500/500**（100 条指令 × 5 例）；`diff.py --limit 400 --branches --rounds 3` **121/122**。
`0x18dc0` 仍不一致，已确认与本轮改动无关（关掉本轮全部改动重跑，输出逐字节相同）。✅

### 三条被差分逼出来的语义错（这一轮）

| 现象 | 真因 |
|---|---|
| 六条标量 FMA 全 0/6，低 4 字节对、上面 12 字节错 | 标量 FMA 的 `127:32` **保留目标原值**，不是取自 `SRC1`。三个独立用例（目标分别全零/负号/普通）各复现一次 |
| `vpackssdw ymm3, ymm4, ymm3` 高半全错 | 边读源边写目标，而目标**就是第二个源** ⇒ 先全读进栈再写 |
| `vinserti128 ymm7, ymm8, xmm7, 1` 整个通道错 | 先搬基址再读要插入的 `xmm7`，而它**就是目标** ⇒ 先把 16 字节搬到栈上 |

- [ ] 每日全量回归：30 万函数 × N 组输入，输出通过率与回归列表
- [ ] 失败最小化：给出触发差异的最小输入
- [x] 逐例故障恢复（`setjmp`/`longjmp` + VEH）：裁判与移植两侧都不再因单个用例崩溃而二分重跑

**验收**：`cargo test --release oracle` 能在 CI 跑完整表；任何一个函数的通过→不通过都会 fail。

## M4 —— 能启动（2–3 个月）

- [ ] 运行时层：CRT 转发、Win32 转发、xmem 实现
- [ ] 文件层：镜像读取（压缩容器）、异步读取
- [ ] 线程/TLS/异常：跑通初始化
- [ ] 首个可达目标：**进到主菜单**（图形仍走旧的翻译层，先求能跑）

**验收**：重编译版能进主菜单并保持 10 分钟不崩；崩溃必须带函数 RVA。

## M5 —— 超过主机（6 个月+）

- [ ] 图形提交边界替换：绘制压进 POD 数组
- [ ] 描述符整块上传 + `SM6.6` heap 直接索引
- [ ] GPU-driven：compute 剔除 + `ExecuteIndirect`
- [ ] 基准：同场景同视角，与 HLE 版（5 fps / 200.7 ms）逐项对比

**验收**：世界场景 ≥ 30 fps（主机目标帧率），CPU 录制 < 10 ms/帧。

## 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 间接调用无法静态解析 | 覆盖率卡在 70–80% | 运行时查表回退（性能损失可接受）；热点函数手工 devirtualize |
| 异常处理 | 部分模块无法重编译 | 第一阶段整体回退原始字节；第二阶段转 SEH |
| 图形层完全不可切 | 退回"翻译 D3D12"，收益归零 | M4 之前就要做一次"提交点识别"预研，确认边界存在 |
| 人力不足 | 停滞在 M2 | M1–M3 是一个人能做完的，先做到那里再谈 L4/L5 |
| 法务 | 项目被下架 | 不含数据、不含产物、工具定位同前作 |
