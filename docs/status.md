# 两把尺子：翻译到哪了，跑到哪了

这个仓库以前只有一个百分比——**99.9%**。那是"能翻成可编译的 C 的函数占多少"，它既真实又
误导：同一时刻，"99.9% 已翻译"和"一帧都画不出来"都是对的，而只有前者听起来像进度。

[PortWatch VI](https://portwatch-vi.xyz/) 把圈子里所有"让这个标题在 PC 上跑起来"的项目放在
一条 0–100% 的刻度上（0 打地基、20 首帧、30 主菜单、40 进世界、50 可玩、100 通关），并且给
每个数字标上是实测还是自述。值得抄的只有这一条判据：**把"写完了"和"能玩了"分开量**。
下面是我们自己的两把尺子，以及每把尺子的读数是怎么来的。

---

## 一、构建标识：这些数字属于哪一个 exe

`.pdata` 表每个构建都不一样，所以没有标识的覆盖率不是事实，是回忆。

```
build  5d493dbdfaa8c425  120,181,760 bytes
       CodeView ba12692a4feb7f424c4c44205044422e/1
       X:/americas/src/sub_story/game/vs_project/Gaming.Xbox.Scarlett.x64/Build/master/game_scarlett_master.pdb
```

| 项 | 取法 | 为什么是它 |
|---|---|---|
| `5d493dbdfaa8c425` | 可执行段（`.text`）的 SHA-256 前 16 位 | 只哈希代码段，改资源不改这个数 |
| `CodeView GUID/age` | 调试目录里 `IMAGE_DEBUG_TYPE_CODEVIEW` 的 `RSDS` 记录 | 链接器写的，**跨构建一定不同**；`PointerToRawData` 是文件偏移，不是 RVA（`pefile.get_data` 只认 RVA，这里得自己 `seek`） |
| PDB 路径 | 同一个 `RSDS` 记录 | 顺带把构建目录结构写出来了：`americas`（项目代号）/ `sub_story` / `Gaming.Xbox.Scarlett.x64` / `Build/master` |

`tools/progress.py` 打印这三样，并把它们和读数一起写进 `docs/progress.tsv`。

## 二、第一把尺子：翻译与验证

| 项 | 读数 | 判据 | 工具 |
|---|---|---|---|
| 翻译量 | **39,976 / 40,002（99.9%）** | 前 4 万个 `.pdata` 函数里，分支通道能产出可编译 C 的比例 | `cover.py --sample 40001 --pass branch` |
| 验证量（指令级） | **609 / 609** | 154 条指令 × 4 例，移植与**原始机器码**逐字节、逐向量寄存器一致 | `diff.py --snippets` |
| 验证量（整函数） | **124 / 125** | 整函数跑完，`xmm0-15` 与 16 KiB arena 一起比 | `diff.py --limit 400 --branches` |
| HLE 面 | **0 / 37** | 7 个 DLL / 37 个导入在 Windows 上不存在，已实现的个数 | `hle.py`、`hle/stubs.c` |

翻译量是分母，验证量是分子——**能被证伪的才算数**。609 例全部一致这句话里的"全部"是有边界
的：`gs:` 段与 IAT 里的地址跨进程不同，`MXCSR` 与 `insertq`/`extrq` 在本机（Intel）跑不了，
这些项在本仓库里被**排除在一致率之外**并单独记账（README §5「一条不能装作没看见的边界」）。
这不是被抹掉的失败，是量具的边界。

## 三、第二把尺子：六级的阶梯

每一级的判据只用台账里有的数，算不出来的不算数（`None` 一律判否）。

| 级 | 名字 | 判据 | 现在 |
|---|---|---|---|
| L0 | 静态覆盖 | 接受率 ≥ 99%，且片段差分无一例不一致 | **[x]** |
| L1 | 闭包能编译 | `closure.py` 把一组互相调用的函数编成一个能链的 `.c` | [ ] |
| L2 | 导入面闭合 | 37 个 `ours` 全有实现，一个只报姓名的桩都不剩 | [ ] 0/37 |
| L3 | 映像能映射 | loader 把 PE 映射进进程，按 `.pdata` 注册展开信息 | [ ] |
| L4 | 入口真的跑了 | 映像里的入口执行了第一条指令（不是片段） | [ ] |
| L5 | 首帧 | GPU 与内存一致性可用，画面出来了 | [ ] |

**现在在 L0，六级里的第一级。** 这不是保守的说法：`tools/` 下没有任何一个加载器，
37 个主机 API 全是桩，GPU 侧一行没有。翻译量 99.9% 与阶梯 1/6 同时成立，正是这一页存在的
理由——两个数字都不假，但只有一个回答"离能玩还有多远"。

## 四、四条轴

PortWatch 用四条轴细分总分（story / rendering / performance / stability）。我们对应的四条：

| 轴 | 现在 | 卡在哪 |
|---|---|---|
| 翻译 | 99.9% | 剩 26 个函数，全要动模型（循环回边标志、PF、`cmpxchg16b`、`insertq`） |
| 验证 | 609/609、124/125 | 唯一不一致仍是 `0x18dc0`；Intel 上无法验证的项无法验证 |
| 外部面 | 0/37 | 37 个主机 API 全是桩；且它们**一个 direct call 都没有**，见 README「HLE 面」 |
| 运行面 | 0/6 级 | 没有加载器，这是最大的一块，也是最没开始的一块 |

翻译与验证这两条已经接近上限，而**外部面与运行面是 0**。这就是为什么上一轮把方向从
"再收 0.1% 的函数"改成了"数清 HLE 面"。

## 五、规矩

1. **每个读数都带构建标识。** 换构建就换一行，不跨构建比较。
2. **自述与实测分开。** `progress.tsv` 里的数只有两种来源：工具刚跑出来的，或明确标注日期的
   历史读数。手写的数字不进台账。
3. **同一构建上任何一项变小 = 回归。** `progress.py` 会打出来并以退出码 2 结束——台账的用处
   就是让变小的东西不可能不被看见。

```
python tools/progress.py                  # 打印标识、最后一行、阶梯
python tools/progress.py --run --tests    # 重测翻译量与片段差分，然后记一行
```

## 六、从 PortWatch 抄了什么，没抄什么

| 它的做法 | 我们 | 为什么 |
|---|---|---|
| 一条 0–100% 的总分 | **改成六级阶梯，每级一个可测判据** | 总分需要把不可比的东西加权；阶梯只回答"下一级是什么" |
| 进度条上的里程碑（首帧 / 主菜单 / 进世界） | **照抄，换成本仓库能测的定义** | 这是它最值钱的判据 |
| 每条标 `Reviewed <日期>` | **照抄，改成构建标识 + 台账** | 日期不如哈希有用 |
| 自述与实测分列 | **照抄** | 我们的"翻译量 vs 验证量"是同一件事 |
| 四条轴细分 | **照抄，换成我们的四条** | — |
| 私建不排名、只列出 | **照抄成语义：本机无法验证的项单独记账** | 已经在 README §5 里 |
| `Scout` 自动发现新仓库、打分算法、排行榜 | **不抄** | 我们在追一个标题，不是在办一场比赛 |
